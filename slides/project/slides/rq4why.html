Fourth: agent design. I took the strongest public workflow, Patchsmith, and analysed 708 of its runs. The key trick is a within-task comparison: on tasks solved by some seeds and failed by others, which behaviours differ? A behaviour check after the last edit separates them strongly. Pytest worked but was rarely used, because the prompt claimed it might be disabled. And the popular advice to reproduce first turns out to be confounded by task difficulty.
